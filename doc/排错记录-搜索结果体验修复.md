# 搜索结果体验修复 —— AI 回复"无相关内容"时展示问题

**日期**: 2026-06-18

---

## 背景

知识库智能问答（搜索 + 对话）在生产使用中反馈了三个体验问题：

1. 用户问"信息安全"，AI 明确回复"没有相关内容"，但下方仍列出"生产安全"等文件的下载链接
2. 下载链接旁显示了文件所属部门/区域信息，用户不希望暴露
3. 点击"下载原文"不触发文件下载，而是跳转浏览器新标签页显示乱码

三个问题分属不同的层面，下面逐一记录。

---

## 问题清单

| # | 症状 | 根因 | 涉及组件 |
|---|------|------|---------|
| 1 | AI 说"没有"但仍有文件链接 | sources 列表与 AI 回答解耦，ES 检索结果无条件返回前端 | Java 后端 Search/Chat Controller |
| 2 | 下载链接旁显示部门名 | 前端 `<el-tag>` 展示了 `deptName` 字段 | Vue 前端 ChatPage / SearchPage |
| 3 | 点击下载跳转新页显示乱码 | MinIO 预签名 URL 被浏览器内联打开，非强制下载 | MinioService → 前端下载链路 |

---

## 详细排错过程

### 问题 1：AI 说"没有相关内容"但仍展示文件下载链接

**现象：**

用户通过搜索框或对话提问"信息安全"，AI（Ollama + RAG）根据 Prompt 规则如实回答"根据已有资料无法确定"，但回答下方仍然列出了 ES 检索返回的"生产安全"相关文件及下载按钮。

**排错：**

1. 检查前端 `ChatPage.vue` / `SearchPage.vue` → `msg.sources` 是后端直接返回的列表，前端仅做展示，无过滤逻辑
2. 检查后端 `ChatController.chat()` → 第 122-136 行，ES 检索结果逐条添加到 `sources` 列表，**无论 AI 最终是否引用了这些文档**
3. 检查 `SearchController.search()` → 同样模式，ES docs 全部塞入 sources
4. AI Prompt 中已规定"如果资料不足以回答问题，请明确说明"，但后端未读取 AI 回复的实际语义

**根因：** 后端架构设计上，ES 检索和 AI 回答是两条独立链路。ES 做关键词/向量匹配返回 topK 文档（"信息安全"匹配到"生产安全"是 BM25 的正常行为），AI 评估文档相关性生成自然语言回答。但 `sources` 列表来自 ES 结果，未与 AI 的"是否找到"判断联动。

**解决：**

在 `SearchController` 和 `ChatController` 中新增 `isNoRelevantAnswer()` 方法，检测 AI 回复是否包含明确表示"未找到"的短语：

```java
private boolean isNoRelevantAnswer(String answer) {
    if (answer == null || answer.isBlank()) return true;
    String s = answer;
    return s.contains("无法确定") || s.contains("没有相关") || s.contains("未找到")
            || s.contains("不足以") || s.contains("没有找到")
            || s.contains("暂无相关") || s.contains("无法回答");
}
```

在获取 AI 回答后、构建返回结果前调用：

```java
// 5. 如果 AI 回答表明未找到相关内容，清空来源文档列表
if (isNoRelevantAnswer(answer)) {
    sources.clear();
}
```

**关键知识点：** RAG 系统的"检索"和"生成"是两个独立步骤。ES 向量相似度 ≠ 语义相关性，AI 的回答才是最终的语义判断。不能假设 ES 返回的文档就是 AI 会引用的文档。

**权衡说明：** 目前的检测基于关键词匹配，存在极小概率的误判（例如 AI 说"关于安全方面无法确定，但关于流程方面..."）。后续可改为让 AI 返回结构化 JSON（含 `relevant: boolean` 字段）来做精确判断。

### 问题 2：文件下载链接展示了部门/区域信息

**现象：**

来源文档的下载按钮旁有一个 `<el-tag>` 显示了部门名称（如"信息技术部"），用户不希望暴露此信息。

**排错：**

直接定位到前端模板 —— `ChatPage.vue` 第 73 行和 `SearchPage.vue` 第 54 行的来源文档卡片中渲染了 `src.deptName`。

**解决：**

移除两处 `<el-tag size="small">{{ src.deptName }}</el-tag>`。`deptName` 字段在后端 DTO 中保留（不影响内部逻辑），仅前端不再展示。

涉及文件：
- `frontend/src/views/ChatPage.vue` — 来源文档卡片中的 deptName 标签
- `frontend/src/views/SearchPage.vue` — 来源文档卡片中的 deptName 标签

### 问题 3：点击"下载原文"跳转新标签页显示乱码

**现象：**

点击搜索结果或对话回复中的"⬇ 下载原文"按钮，浏览器在新标签页打开 MinIO 预签名 URL，显示为乱码字符（对文本文件）或二进制数据（对 PDF/Office 文件），没有触发文件下载。

**排错：**

1. 检查前端 — `<a :href="src.downloadUrl" target="_blank">` 直接使用 MinIO 预签名 URL
2. 检查后端 — `MinioService.getPresignedUrl()` 返回的是 MinIO 的 HTTP GET 直链
3. 浏览器行为 — 对 `target="_blank"` 的 GET 请求，浏览器默认尝试内联渲染（inline display），而非下载
4. 尝试加 `download` 属性 — 无效，因为 MinIO URL 是跨域的，`download` 属性仅对同源 URL 生效
5. 检查 JWT 认证 — 直接用 `<a>` 标签导航无法携带 `Authorization: Bearer` 请求头（浏览器的页面导航不经过 axios 拦截器）

**根因（三层叠加）：**

| 层 | 问题 |
|----|------|
| **MinIO 预签名 URL** | 生成的是普通 GET 链接，MinIO 不强制设置 `Content-Disposition: attachment` |
| **浏览器行为** | `target="_blank"` 导航触发内联渲染，不触发下载 |
| **JWT 认证** | `<a>` 标签的页面导航不经过 axios 拦截器，无法携带 Authorization 头 |

**解决：**

采用**后端代理下载 + 前端 Blob 下载**方案：

**后端** — `BrowseController.java` 新增 `GET /api/browse/download/{fileId}` 端点：

```java
@GetMapping("/download/{fileId}")
public void downloadDocument(@PathVariable String fileId,
                              HttpServletResponse response) throws IOException {
    // 1. 查 Document 表获取 minioPath 和 fileName
    Document doc = docRepo.findById(fileId).orElse(null);
    // 2. 从 MinIO 读取文件流
    InputStream in = minioService.getDocumentStream(objectPath);
    // 3. 设置 Content-Disposition: attachment 强制浏览器下载
    response.setHeader("Content-Disposition",
            "attachment; filename=\"" + encodedName
            + "\"; filename*=UTF-8''" + encodedName);
    // 4. 流式写出
    in.transferTo(response.getOutputStream());
}
```

**后端** — `MinioService.java` 新增 `getDocumentStream()` 方法：

```java
public InputStream getDocumentStream(String objectPath) {
    return minioClient.getObject(GetObjectArgs.builder()
            .bucket(bucketDocs).object(objectPath).build());
}
```

**前端** — 下载按钮改为 `@click` 触发，通过 axios（带 JWT header）请求代理端点，拿到 Blob 后创建临时 Object URL 触发浏览器下载：

```typescript
async function downloadFile(fileId: string, fileName: string) {
  const response = await http.get(`/browse/download/${fileId}`, {
    responseType: 'blob',
  })
  const url = window.URL.createObjectURL(new Blob([response.data]))
  const link = document.createElement('a')
  link.href = url
  link.download = fileName
  document.body.appendChild(link)
  link.click()
  document.body.removeChild(link)
  window.URL.revokeObjectURL(url)
}
```

**前端** — 消息区增加事件委托，拦截 markdown 中渲染的下载链接（同样走 axios 认证下载）：

```typescript
function handleMessageClick(e: MouseEvent) {
  const target = e.target as HTMLElement
  if (target.tagName === 'A' && target.getAttribute('href')?.startsWith('/api/browse/download/')) {
    e.preventDefault()
    // 提取 fileId 和 fileName，调用 downloadFile()
  }
}
```

**完整调用链（修复后）：**

```
用户点击"下载原文"
  → axios GET /api/browse/download/{fileId}（带 JWT Authorization 头）
    → BrowseController.downloadDocument()
      → docRepo.findById(fileId) → 获取 minioPath + fileName
      → minioService.getDocumentStream(minioPath) → MinIO 文件流
      → response.setHeader("Content-Disposition", "attachment")
      → 写出文件流
  → 前端收到 Blob
  → URL.createObjectURL + <a>.click() → 浏览器触发下载
```

**关键知识点：**

1. **`Content-Disposition: attachment`** 是强制浏览器下载的标准方式，`inline` 则是浏览器默认行为（尝试内联展示）
2. **`<a download>` 属性仅对同源 URL 有效**，跨域 URL（如 MinIO 预签名链接）无效
3. **`<a>` 标签的页面导航不经过 axios 拦截器**，无法携带自定义 Header（如 JWT），因此对于需要认证的文件下载，必须用 `fetch`/`axios` 先获取数据，再通过 Blob URL 触发下载
4. **文件名编码**：`Content-Disposition` 头中非 ASCII 文件名需要同时提供 `filename`（URL 编码）和 `filename*=UTF-8''`（RFC 5987）两种格式，兼容不同浏览器

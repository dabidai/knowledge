# 后续计划

## 1. RAG 意图识别 —— 按需注入结构化数据

**现状**：每次提问都同时查 ES 文档正文 + items 表标题关键词匹配，签阅记录无条件跟随。

**问题**：
- 用户只问文档内容时，标题关键词可能偶然命中事项 → 无关签阅记录被织入上下文 → 浪费 token 并可能干扰回答
- 用户明确问签阅/事项信息时，当前方案足够

**方案**：在 RAG 管道前加一层轻量意图分类：

```
用户问题 → 意图分类器
  ├── 类型A: 文档内容查询   → 只查 ES，不查结构化数据
  ├── 类型B: 事项信息查询   → 查 items 表 + ES
  └── 类型C: 签阅/人员查询   → 查 items + opinions + ES
```

实现方式：给 AI 加一个极简的分类 prompt（一次额外 API 调用），或直接用规则匹配（关键词白名单："谁签了"、"签约人"、"签阅"、"发文单位"、"文号" 等 → 查结构化数据）。

预期效果：减少无关结构化数据注入，提升回答精准度。

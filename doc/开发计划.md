## 三、执行顺序

按优先级排列，遵循「先修体验、再补功能、最后加固」原则：

| 优先级 | 编号 | 任务 | 预估工作量 | 原因 |
|--------|------|------|-----------|------|
| P0 | 2.1.4 | Markdown 渲染优化 | 小 | 当前正则替换太简陋，影响核心体验 |
| P0 | 2.4.1 | 后端单元测试 | 中 | 保证后续改动不回归 |
| P1 | 2.2.1 | 导入断点续传 | 大 | 100GB 数据导入中断后重头来代价太大 |
| P1 | 2.2.4 | Swagger API 文档 | 小 | 前后端联调必需 |
| P1 | 2.3.4 | 健康检查完善 | 小 | 运维基本需求 |
| P2 | 2.1.2 | 搜索页增强 | 中 | 提升检索体验 |
| P2 | 2.2.2 | 搜索筛选增强（后端） | 中 | 配合前端筛选 |
| P2 | 2.3.1 | 请求限流 | 小 | 安全基本要求 |
| P3 | 2.1.1 | 全局加载与错误状态 | 中 | UI 润色 |
| P3 | 2.1.3 | 图谱交互增强 | 中 | 交互优化 |
| P3 | 2.1.5 | 导入页面优化 | 中 | 体验优化 |
| P3 | 2.2.3 | 交叉引用深度检测 | 大 | NLP 依赖，准确率不确定 |
| P3 | 2.3.2 | 输入校验增强 | 小 | 安全加固 |
| P3 | 2.3.3 | 日志脱敏 | 小 | 安全合规 |

## 一、使用手册

### 1.1 系统简介

这是一个面向政府公文/事项的**智能知识库**系统，核心能力：

- **智能问答（RAG）**：基于本地大模型对导入的文档进行检索增强问答
- **混合检索**：关键词（BM25）+ 语义向量（KNN）融合检索，支持分类/年度/事项类型筛选
- **知识图谱**：以图形式展示事项、文档、签阅人之间的关系
- **数据导入**：支持 CSV 元数据与 OFD/PDF/Office 文档分开导入并自动匹配

### 1.2 访问地址

| 环境 | 地址 | 说明 |
|------|------|------|
| 生产（服务器） | `http://<服务器IP>/` | Nginx 80 端口反代 |
| 后端 API | `http://<服务器IP>:8080` | Spring Boot |
| 本地开发 | `http://localhost:3000` | Vite dev server，`/api` 代理到 8080 |
| AI 服务 | `http://localhost:8000` | FastAPI（一般不需直接访问） |

### 1.3 登录与权限

- 所有页面（除登录外）均需登录，登录凭证为 JWT，有效期 **7 天**
- 系统分两种角色：

| 角色 | 可用功能 | 不可用 |
|------|----------|--------|
| 普通用户 | 智能问答、全文检索、文档浏览、知识图谱 | 导入、用户/部门管理、导入历史 |
| 管理员 | 以上全部 | — |

- **数据权限**：用户只能检索到**本部门**的文档，以及标记为**公共（isPublic=true）**的文档
- 首次部署需初始化管理员账号（后端 `POST /api/users/init`）

### 1.4 功能模块使用说明

#### ① 智能问答 `/chat`

对知识库内容提问，系统返回带引用的回答：

- 支持多轮对话（保留最近 10 轮上下文）
- 回答末尾标注信息来源（文档名称或事项文号）
- 信息不足时明确回复"根据已有资料无法确定"，不会编造
- 与知识库无关的日常问题也可正常闲聊

#### ② 全文检索 `/search`

混合检索入口，输入关键词或自然语言：

- **检索方式**：BM25 关键词 + 语义向量（KNN），RRF 融合排序
- **结果高亮**：命中片段用 `<em>` 高亮展示
- **筛选条件**：事项分类、年度、事项类型
- **权限过滤**：自动按当前用户部门 + 公共文档过滤

#### ③ 文档浏览 `/browse`

按目录树浏览已导入的文档，支持在线查看与下载。

#### ④ 知识图谱 `/graph`

以图形化方式展示事项与文档、签阅人等实体关系（基于 Neo4j）。

#### ⑤ 数据导入 `/import`（仅管理员）

详见下节"数据导入指南"。

#### ⑥ 导入历史 `/history`（仅管理员）

查看所有导入任务的状态（进行中/成功/失败/孤儿任务自动标记失败），支持：

- 查看进度与失败详情
- 失败任务**重试**
- 删除历史任务记录

#### ⑦ 用户管理 `/users` 与部门管理 `/departments`（仅管理员）

创建/删除用户、维护部门列表。部门用于检索权限过滤和文档归属。

### 1.5 数据导入指南

支持 **CSV 元数据** 与 **OFD / PDF / Word 等文档文件**，二者可分开导入、自动匹配：

**推荐流程：**

1. **先导入 CSV** —— 创建 `expected`（待匹配）记录，含事项标题、分类、文号、发文单位、年度、类型等元数据
2. **后导入文档** —— 系统按文件名（不含扩展名）模糊匹配 `expected` 记录，匹配成功状态变为 `matched`

**导入方式（三种）：**

| 方式 | 说明 |
|------|------|
| 上传文件 | 通过浏览器上传到服务器 |
| 服务器路径 | 导入服务器 `IMPORT_ROOT_DIR` 下指定目录的文件 |
| 目录浏览导入 | 后端接口列出目录，选择后导入 |

**重要特性：**

- **幂等性**：按文档 ID 查重，重复导入不会产生重复数据（存在则更新）
- **多次追加**：支持多次导入不同目录，数据追加入库
- **大文件支持**：单文件最大 2048MB，ES 请求体限制已调至 500MB

**文档解析与 OCR：**

| 文件类型 | 解析方式 |
|----------|----------|
| PDF | **双轨并行**：优先提取原生文字 → 逐页质量检查 → 不合格页自动降级为 OCR 识别 |
| OFD / Office | 转换为文本后走与 PDF 相同链路 |

- 扫描件 / 纯图片 PDF：原生文字提取几乎为空，会自动整页走 **Tesseract OCR**（中文简体 `chi_sim` + 英文 `eng`，渲染 DPI 200）
- 质量判定：单页有效字符数 < 20 或 Unicode 有效字符占比 < 45% 时触发 OCR（阈值见后端 `application.yml` 的 `pdf:` 段）
- 解析结果带质量等级（全文本 / 部分 OCR / 全 OCR），OCR 页数占比越低越好
- Tesseract 语言数据目录：`/usr/share/tesseract-ocr/5/tessdata`（`ocr.tessdata-path`，容器内）

### 1.6 日常使用注意事项

- 检索不到文档时，先确认：是否已登录、文档所属部门是否与当前用户一致、文档是否标记公共
- 问答结果引用不清晰时，可到 `/search` 用关键词再验证一遍
- 导入大文件（尤其 OFD）时耐心等待，可在 `/history` 查看实时进度

## 二、数据库与向量数据库连接信息

### 2.1 组件总览

当前系统共使用 **5 个数据存储/中间件 + 2 个 AI 服务**，均以 Docker Compose 编排：

| # | 组件 | 容器名 | 作用 | 对外端口 |
|---|------|--------|------|----------|
| 1 | PostgreSQL 16 | `kb-postgres` | 业务数据库（用户/部门/文档/事项/意见/导入任务） | 5432 |
| 2 | Elasticsearch 8.15（IK 分词） | `kb-es` | **全文检索 + 向量数据库**（1024 维 dense_vector） | 9200 |
| 3 | Redis 7 | `kb-redis` | 缓存（登录态/会话等） | 6379 |
| 4 | MinIO | `kb-minio` | 对象存储（原始文件 + 解析后的 Markdown） | 9000/9001 |
| 5 | Neo4j 5（Community） | `kb-neo4j` | 知识图谱图数据库 | 7687/7474 |
| 6 | AI 服务（FastAPI） | `kb-ai` | Embedding 生成 + RAG 问答 | 8000 |
| 7 | Ollama（宿主机） | — | 本地大模型推理（qwen3:32b） | 11434 |

> **说明**：本系统的**向量数据库是 Elasticsearch**（`contentVector` 字段，1024 维稠密向量），而不是独立的向量库如 Milvus/FAISS。Embedding 模型为 `BAAI/bge-large-zh-v1.5`。

| 组件 | 主机 | 端口 | 用户名 | 密码 | 数据库/索引 |

| Elasticsearch | localhost / `elasticsearch` | 9200 | —（已关闭安全） | — | 索引 `doc_index` |
| Redis | localhost / `redis` | 6379 | — | —（无密码） | — |
| MinIO API | localhost / `minio` | 9000 | `root` | `12345678` | 桶 `knowledge-docs`、`knowledge-md` |

### 2.3 PostgreSQL —— 业务数据库

- **镜像**：`postgres:16-alpine`
- **数据库名**：`knowledge`
- **连接串（本地）**：`jdbc:postgresql://localhost:5432/knowledge`
- **连接串（Docker 内）**：`jdbc:postgresql://postgres:5432/knowledge`
- **回退默认**：用户 `kb_user` / 密码 `12345678`（Compose 未覆盖时）
- **调优参数**：`shared_buffers=1GB`、`effective_cache_size=3GB`、`max_connections=50`

**主要数据表**（JPA `ddl-auto: update` 自动建表）：

| 表 | 用途 |
|----|------|
| `documents` | 文档/文件映射（含导入状态：expected / matched） |
| `items` | 事项（标题、分类、文号、发文单位、年度、类型） |
| `opinions` | 签阅意见（签阅人、时间、意见） |
| `import_tasks` | 导入任务（进度、状态、错误信息） |
| `users` / `departments` | 用户与部门 |
| `conversations` / `messages` | 问答会话与消息记录 |

**常用查询：**

```bash
docker exec kb-postgres psql -U root -d knowledge -c \
  "SELECT status, COUNT(*) FROM documents GROUP BY status;"
docker exec kb-postgres psql -U root -d knowledge -c "SELECT COUNT(*) FROM items;"
```

### 2.4 Elasticsearch —— 检索引擎 + 向量数据库

- **镜像**：`kb-es:8.15.0-ik`（内置 IK 分词器）
- **安全**：`xpack.security.enabled=false`（无认证）
- **索引**：`doc_index`（后端启动时自动创建，删除后重启会自动重建）
- **分词**：`ik_max_word`
- **向量**：`contentVector` 字段，`dense_vector` 类型，**1024 维**
- **混合检索**：BM25 关键词 + KNN 向量，`k` / `numCandidates` 由后端计算，RRF 融合
- **大文件适配**：`http.max_content_length=500mb`，批量写入每批 200 条，避免 OFD 大文件 413

**索引 Mapping 核心字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `docId` | keyword | 文档 ID |
| `fileName` / `deptName` | keyword | 文件名 / 部门（权限过滤） |
| `isPublic` | boolean | 是否公共文档 |
| `itemTitle` / `content` | text (ik_max_word) | 标题 / 正文（检索 + 高亮） |
| `itemCategory` / `itemYear` / `itemType` | keyword/integer | 分类 / 年度 / 类型（筛选） |
| `contentVector` | dense_vector(1024) | 语义向量 |
| `minioPath` | keyword | Markdown 在 MinIO 的路径 |

**常用命令：**

```bash
curl -s http://localhost:9200/_cat/indices?v                 # 查看索引
curl -s http://localhost:9200/doc_index/_count               # 文档块数量
curl -X DELETE http://localhost:9200/doc_index               # 删除（重启后端自动重建）
```

### 2.5 Redis —— 缓存

- **镜像**：`redis:7-alpine`
- **无密码**，默认 0 号库
- **持久化**：AOF（`--appendonly yes`）
- **内存策略**：`maxmemory 512mb`，`allkeys-lru`

```bash
docker exec kb-redis redis-cli ping     # 输出 PONG 表示正常
```

### 2.6 MinIO —— 对象存储

- **API 端口**：9000；**控制台**：9001
- **凭证（实际）**：`root` / `12345678`（回退默认 `kb_admin` / `12345678`）
- **Bucket**：

| Bucket | 存放内容 |
|--------|----------|
| `knowledge-docs` | 上传的原始文档（public 目录） |
| `knowledge-md` | 解析后的 Markdown 文本 |

- 后端通过预签名 URL 提供下载（有效期 7 天）

```bash
# 控制台浏览器访问：http://localhost:9001
```

### 2.7 Neo4j —— 知识图谱

- **镜像**：`neo4j:5-community`
- **认证**：`neo4j` / `12345678`（回退默认 `neo4j_pass`，注意与 `AGENTS.md` 中的旧命令不一致时以 `docker/.env` 为准）
- **端口**：Bolt 7687 / HTTP 7474（浏览器管理界面）
- **内存**：堆初始 2g / 最大 4g，PageCache 1g

```bash
docker exec kb-neo4j cypher-shell -u neo4j -p 12345678 "MATCH (n) RETURN count(n) AS nodes;"
```

### 2.8 AI 服务（FastAPI）与 Ollama

**AI 服务（容器 `kb-ai`，端口 8000）：**

| 接口 | 方法 | 说明 |
|------|------|------|
| `/health` | GET | 健康检查 |
| `/embed` | POST | 单条文本生成向量 |
| `/embed-batch` | POST | 批量生成向量 |
| `/ask` | POST | 单轮 RAG 问答 |
| `/chat` | POST | 多轮 RAG 对话 |

**配置：**

| 项 | 值 |
|----|-----|
| Embedding 模型 | `BAAI/bge-large-zh-v1.5`（1024 维，模型缓存于 `./data/ai-models`） |
| Embedding 后端 | `EMBEDDING_BACKEND`：`pytorch`（默认）/ `onnx` |
| 推理后端 | Ollama（`qwen3:32b`），地址 `http://host.docker.internal:11434` |

**ONNX 加速**：Embedding 可选 ONNX 后端（`CPUExecutionProvider`），模型已预先导出在 `ai-service/onnx-model/`（sentence-transformers ONNX 格式，含 `onnx/`、tokenizer 等文件），加载失败时自动回退 PyTorch。ONNX 后端免运行时依赖 PyTorch，CPU 推理更快。

**重要**：Embedding 模型维度（1024）与 ES `contentVector` 的 `dims(1024)` **必须一致**，更换模型维度会不匹配导致检索异常。

## 三、运维速查

### 查看服务状态

```bash
ss -tlnp | grep -E '8000|8080|3000'          # 应用端口
docker ps --format 'table {{.Names}}\t{{.Status}}'   # 容器状态
```

### 数据清理（保留用户/部门）

```bash
# PostgreSQL
docker exec kb-postgres psql -U root -d knowledge -c \
  "TRUNCATE documents, items, opinions, import_tasks RESTART IDENTITY CASCADE;"

# ES 索引（重启后端自动重建）
curl -X DELETE http://localhost:9200/doc_index

# Neo4j 清空
docker exec kb-neo4j cypher-shell -u neo4j -p 12345678 "MATCH (n) DETACH DELETE n;"

# MinIO 文件
docker exec kb-minio sh -c "rm -rf /data/knowledge-md/markdown && mkdir -p /data/knowledge-md/markdown"
docker exec kb-minio sh -c "rm -rf /data/knowledge-docs/public && mkdir -p /data/knowledge-docs/public"
```

### 查看日志

```bash
tail -50 ~/llm/docker/anythingllm/knowledge/backend/app.log      # 后端
tail -50 ~/llm/docker/anythingllm/knowledge/frontend/frontend.log # 前端
tail -20 ~/llm/docker/anythingllm/knowledge/ai-service/ai-service.log # AI
```

### 安全提醒

- 当前默认凭证（`12345678` 等）随仓库公开，**上线前必须修改** `docker/.env`
- 已修改的凭证不要提交到 git
- 如需更换 Embedding 模型，必须同步调整 ES `contentVector` 维度

# 实施路线与协同验收

这是开发与验证方案，不是已执行的修复记录。建议按依赖顺序推进，每阶段都有独立交付与停止条件，不以“重写系统”作为起点。

## 1. 分阶段实施

| 阶段 | 对应问题 | 修改责任范围 | 交付及通过条件 |
|---|---|---|---|
| A：统一读取与交互边界 | C01/C02/C15/C20/C21/C22/C27 | 安全策略、ES 查询、SQL/图/下载/会话服务、缓存 key、Vue 页面和 DTO | 所有入口使用同一授权范围；图谱 ID 正确；页面旧响应不串会话；不可信 HTML 不执行 |
| B：导入结果可信 | C03/C05/C06/C08/C11/C13/C14/C18/C23 | Import/CSV/ES/MinIO/AI 网关、健康检查、前端进度 | 限定匹配范围；向量与 bulk 错误可见；重试进入同一执行器且不允许活动任务重复；完成后缓存更新；筛选契约贯通 |
| C：持久任务与版本发布 | C04/C07/C09/C10/C12 | 数据模型迁移、manifest/runner/outbox、文档版本、图消费者 | 来源持久；重启恢复；签阅/阶段幂等；先验证新版本再发布；局部失败能局部重试 |
| D：资源隔离与检索质量 | C16/C17/C19/C25/C26 | Python 执行容量、deadline、统一 Retrieval/Context 服务、解析质量与输入限制 | 导入不饿死在线请求；回答/证据映射；长文不静默丢失；配额与故障降级可测 |
| E：部署与运行闭环 | C24/C28，复核全部 | 配置/镜像/启动、对账、指标、CI/集成测试与运行手册 | 新环境可复现启动；故障矩阵通过；版本/差异可观测；备份恢复演练通过 |

这些是逻辑阶段，不是工期承诺。C 阶段涉及 schema/outbox 等数据库写入，执行前必须另行允许并备份；B 阶段 ES schema 补充和历史索引回填同样不能未经允许执行。可以先完成只读验证、DTO 和代码准备，再审阅具体迁移方案。

### A 阶段的具体开发顺序

1. 新增 AccessScope/AccessPolicyService，从数据库当前用户角色和部门构建范围，确定管理员是否统一读取全部。
2. ES 两分支预过滤、SQL 事项过滤、图详情过滤、正文/下载鉴权、会话追加校验；未授权请求不能提前创建消息或签发 URL。
3. 同步调整缓存权限指纹并废弃旧 key；缓存命中也测试权限变化。
4. 增加图谱专用事项搜索；前端路由/请求参数区分文档与事项 ID。
5. 禁用原生 HTML 与统一安全渲染；把会话/选择 ID 和请求序号纳入页面更新条件；处理卸载清理。

### B 阶段的最小过渡方案

在 C 的持久任务落地前，先让 processDocument 返回 DocumentProcessResult；批量索引返回失败项；embedding 校验 cardinality/dimension；批次支持部分失败及准确计数。统一 retry 的异步调度并加活动状态冲突判断。

不能宣称这时已解决进程崩溃丢队列或跨存储一致性。暂时只在单实例运行，暴露这些限制；修复 Markdown 路径、完成阶段缓存失效、健康 false 检查、筛选和异常语义。匹配歧义时安全停止该条目，不再自动全库覆盖。

### C 阶段的迁移和回退

1. **只读调查**：统计签阅重复、同名/同 ID 冲突、孤立关联、ES 缺块和版本缺失，出冲突清单；禁止自动删重。
2. **审阅迁移**：新增表/字段/约束，状态长度扩容，历史兼容读取和版本默认策略，列出每项写入影响。
3. **允许与备份**：明确数据库实例/索引/图/对象范围，备份 PG 与不能从主库恢复的对象；ES/Neo4j 如要修改/删除也按数据库约束先备份。实际命令应针对现场版本制定，本文不提供一键清理。
4. **隔离演练**：在脱敏副本验证迁移、恢复、约束冲突和双读兼容；不要用生产启动器执行实验。
5. **扩展兼容**：先新增结构，保留旧读路径；有限范围双写/影子校验，记录遗漏，不把双写视为天然可靠。
6. **分批回填**：按稳定主键与 checkpoint 可恢复；候选 ES/图版本不影响当前查询；对账无差异再切读。
7. **回退**：切回旧发布指针/索引 alias/兼容读路径；已新增的合法业务记录保留并安排反向兼容，不能简单“回滚 DDL”声称无损。
8. **延迟清理**：观察期与备份恢复确认后，才申请清理旧字段/对象/索引；保留审计和恢复说明。

## 2. 隔离验收数据集

建立人工可核对的小样本，每份文档/事项/签阅预先列明范围、身份、版本和预期数量：

- 甲、乙两个部门，各有普通用户；甲部门另有管理员；一个公共区。
- 两部门各一份同名通知；同部门两个子目录也有同名文件，内容不同。
- 一事项两份文件、一人同时间的两条合法不同签阅；另设重复导入同条签阅的样本。
- 长文后半部包含唯一事实，超过当前 100 块；包含表格、短条款、英文附件的文档。
- PDF 原生、扫描、混合、单页失败、空白、异常文件；格式扩展名与内容不符样本。
- 多份同类型 CSV；文档先到、事项后到、映射先到、签阅先到的排列。
- 两个用户各有会话；聊天/正文请求能够人为延迟并倒序返回。
- 文档/文件名/模型回答包含无害的 HTML 测试载荷，仅在隔离环境验证不会执行。

不要在验证日志里保留真实敏感正文、密码、JWT 或长期下载签名。mock 用于准确模拟协议失败，真实隔离存储用于验证一致性和授权，二者都需要。

## 4. “协调”指标与初始门槛

以下数值是建议验收目标，尚未实测；性能指标需绑定硬件、模型、并发和文档规模。

| 维度 | 建议初始验收门槛 | 采集位置 |
|---|---|---|
| 权限 | 全部隔离场景泄漏 0，包括模型上下文及缓存 | API/证据审计/授权用例 |
| 真实完成 | 标记可检索成功的文档，目标块和向量缺失 0 | manifest + ES 对账 |
| 幂等 | 同样输入多次提交后，业务与图数量稳定，版本策略可解释 | SQL/图查询与对象清单 |
| 恢复 | 已接纳任务丢失 0，过期租约恢复有记录 | runner/outbox 指标 |
| 发布 | 候选失败不影响旧 activeVersion，过期 worker 发布 0 | 版本指针和 fencing 验收 |
| 可见性 | 文档发布后树/检索建议 10 秒内更新，图建议 60 秒内收敛 | 各投影版本/延迟 |
| 卡住判定 | 超过阶段预算或租约期限必有 stalled/retry/failed 与原因 | 心跳、队列年龄、deadline |
| 交互 | 导入期间纯检索 P95 相对无导入基线劣化建议不超过 20% | 分路径延迟指标 |
| 生成 | 单独记录排队、首结果/总耗时、超时率；按目标模型设门槛 | AI/turn trace |
| 质量 | 末尾事实、签阅与引用样本均有预期证据；额外统计 Recall@K/引用正确率 | 固定脱敏评测集 |

权限与成功语义是硬门槛；性能和收敛时间可以依据现场能力调整，但必须写下明确值并测试。不能用增加 timeout 或无限重试“解决”卡住。

## 5. 对账、告警与运维顺序

只读对账建议核对：PG activeVersion 对象 hash/大小、ES chunkCount/维度/元数据与版本、图实体/关系版本、任务 remaining/lease、孤立对象和待关联数。报告区分暂时滞后与超过期限的不一致，不以 count 相等代替逐身份/版本核对。

日志统一 traceId/requestId/batchId/entryId/docId/version/turnId；指标至少包括队列长度与最老年龄、阶段 P95、retry 次数、bulk 单项失败、空正文/截断/错误页数量、投影滞后、缓存失效失败、各模型容量与超时率。

出现问题时：先查能力状态与 trace → 定位批次/条目/阶段 → 生成只读差异报告 → 判断能否从原始来源重试该阶段 → 获得适用写入允许并备份 → 执行有范围/可回退的补偿 → 再对账确认。不要先清空库、索引或图。

部署运行最好由 systemd 或容器管理进程，支持就绪检查、自动恢复与优雅退出。停机先停止接纳任务，再等待受预算约束的在途阶段并记录 checkpoint；重启从持久清单恢复，不依赖 30 秒内完成数小时导入。

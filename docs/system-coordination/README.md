## 最先处理的五件事

1. 统一服务端资源权限，包括 KNN、事项/签阅、正文/下载、图谱、会话和缓存。
2. 文件身份必须限定数据范围，取消全库同名覆盖与模糊匹配首条即命中。
3. 任务成功必须有可核对的结果：解析、对象存储、向量及 ES 的失败不能伪装完成。
4. 首次导入与重试统一调度；重试只执行失败阶段，重启后能找回任务来源。
5. 修复图谱 ID、筛选字段、缓存失效时机与健康检查等前后端契约。

## “协调”的验收定义

- 同一版本文档的原文、正文、事项、检索与图谱信息能够关联并核对。
- 同一用户通过浏览、检索、问答、图谱和下载看到相同的权限边界。
- 一个组件故障时，页面明确显示失败或降级；不丢任务、不重复业务记录、不输出虚假成功。
- 后台变更后，缓存和前端在约定的可见性期限内更新。
- 重复提交、重试、重启、版本切换后，数据仍满足约束。
- 每个处理中任务都有责任阶段、最后活动时间、恢复方式与可关联日志。

文档可以定义目标和验证方法；“不存在卡死、僵化和协作问题”需要实施后通过隔离环境中的故障注入、集成验证及生产观察证明，当前不能据静态阅读作出保证。
